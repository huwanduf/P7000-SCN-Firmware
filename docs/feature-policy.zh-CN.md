# 功能取舍与 SCN 风格

[English](feature-policy.md) | 简体中文

项目优先保留各场景原厂的色彩、曝光和拍摄处理组合，在这条链上开放兼容选项。面对老平台，控制改动范围、复用原生参数接口和不额外阻塞显示线程，是当前运行稳定性策略；这不等于已经测得所有卡顿都是芯片算力不足。

| 项目 | 当前策略与依据 |
|---|---|
| WB | 保留每个场景的原厂白平衡，再叠加共享 ±6 两轴偏移；不开放完整预设/色温列表，保持场景色彩基调 |
| 优化校准 | 使用场景原始锐度、饱和度和对比度，SCN 入口保持灰显；早期自定义入口有黑屏反馈，已撤回 |
| 最低快门 | SCN 行灰显，曝光时长由场景程序判断；早期强制下限尝试未达到预期，V3.2 已撤销，普通模式保留原行为 |
| 连拍 | 保留原场景策略；新增连拍提交同时牵涉画质、尺寸和 ISO，恢复路径尚未充分验证，暂缓跨场景开放 |
| 降噪/自定义优化校准 | 保留场景处理与原厂限制，不改写普通模式和用户优化校准 |
| 我的菜单 | 保留用户六槽配置，逐项检查目标和场景条件，不把全部槽位强制标为可用 |
| P7100 参考 | 只作为比较研究线索；布局和平台不同，不把未验证跨机型代码加入固件 |
| 性能 | 不改芯片时钟、硬件初始化与校准。仍有菜单/返回取景停顿反馈，尚无已证实的整体加速 |
| 电量 | 复用原厂七档缓存并合并成五格，不虚构电压、逐 1% 容量或电池健康度；不在 UI 中新增会等待 MCU 的同步查询 |

“保留风格”说明当前功能定位，“未实现”说明尚未完成的工作，“未验证”说明证据边界。历史缺陷不会改写为已成功实现的设计。
